# Data တွေကို ဘယ်လို သိမ်းဆည်းထားသလဲ?

Software လောကမှာ၊ ယုံကြည်မှုဆိုတာ ကိုယ့် Data တွေ ဘယ်မှာရှိနေလဲ သိရှိခြင်းအပေါ်မှာ တည်ဆောက်ထားတာပါ။ Orchestra Sync က သင့် Data တွေကို နေရာ နှစ်နေရာ ခွဲခြား သိမ်းဆည်းပါတယ်။

## ၁။ သင်၏ လျှို့ဝှက်ခန်း (Client Storage)
သင့် လျှို့ဝှက်ချက်တွေက သင်နဲ့ပဲ သက်ဆိုင်ပါတယ်။
*   **GitHub Token (PAT):** ဒီ အရေးကြီးတဲ့ သော့ကို သင့်စက်ရဲ့ `figma.clientStorage` မှာပဲ သိမ်းဆည်းပါတယ်။ ဆိုလိုတာက သင့် Browser (သို့) Desktop App ထဲမှာပဲ ရှိနေမှာပါ။ Figma File ပေါ်မှာ လုံးဝ (လုံးဝ) သွားမသိမ်းပါဘူး။ တခြား Designer တွေ ဒီဖိုင်ကို ဖွင့်လိုက်ရင် သင့် Token ကို မြင်ရမှာ မဟုတ်သလို၊ သုံးလို့လည်း ရမှာ မဟုတ်ပါဘူး။ သူတို့ ကိုယ်ပိုင် Token ကို ထည့်သွင်း အသုံးပြုရပါမယ်။
*   **Personal Preferences:** Repo Owner နဲ့ Name လိုမျိုး ဖြည့်စရာတွေကို အလွယ်တကူ ပြန်ပေါ်လာစေဖို့ ဒီနေရာမှာ Cache အနေနဲ့ မှတ်သားထားပါတယ်။

## ၂။ မျှဝေသုံးစွဲသည့် မှတ်တမ်း (Plugin Data)
*ချိတ်ဆက်မှု* နဲ့ ပတ်သက်တဲ့ Configuration တွေကတော့ Figma File ထဲမှာ ရှိနေပါတယ်။
*   **Sync Settings:** ဘယ် Collections တွေက ဘယ် Groups နဲ့ ချိတ်ဆက်ထားလဲ၊ ဘယ် Branch ကို ပို့မှာလဲ၊ Repo Name က ဘာလဲ စတာတွေကို `figma.root.getPluginData` မှာ သိမ်းဆည်းပါတယ်။
*   **Shared Context:** ဆိုလိုတာက သင် Project တစ်ခုကို Setup လုပ်ပြီး သင့်အဖွဲ့သားကို ဖိုင်လွှဲပေးလိုက်ရင်၊ သူတို့လည်း ဒီ Configuration (Repo, Path, Groups) တွေကို မြင်ရမှာပါ။ သူတို့က Sync လုပ်ချင်ရင် သူတို့ရဲ့ Auth Token လေး ရိုက်ထည့်လိုက်ရုံပါပဲ။

## ၃။ နောက်ဆုံး မှတ်တမ်းတိုက် (GitHub)
နောက်ဆုံးထွက်လာတဲ့ ရလဒ်ဖြစ်တဲ့ JSON design tokens တွေကိုတော့ သင့်ရဲ့ GitHub Repository မှာ သိမ်းဆည်းပါတယ်။
*   ဒါဟာ ပုံမှန် Text File (JSON) တစ်ခုပါပဲ။
*   သင့် Codebase သမိုင်းကြောင်းရဲ့ အစိတ်အပိုင်း တစ်ခုအဖြစ် ထာဝရ တည်ရှိနေမှာပါ။
*   Sync လုပ်လိုက်တိုင်းမှာ "Commit" အသစ်တစ်ခု ဖြစ်ပေါ်လာပြီး၊ ဘယ်အရာတွေ ပြောင်းလဲသွားလဲ၊ ဘယ်သူ ပြောင်းလိုက်တာလဲ၊ ဘယ်အချိန်ကလဲ ဆိုတာတွေကို အတိအကျ ပြန်ကြည့်လို့ရတဲ့ မှတ်တမ်း ကျန်ရစ်နေမှာ ဖြစ်ပါတယ်။
