# သတိပြုရန် အချက်များ (Best Practices)

လုပ်ပိုင်ခွင့်တွေ ကြီးမားလာတာနဲ့အမျှ တာဝန်ယူမှုလည်း ကြီးမားလာပါတယ်။ Orchestra Sync က သင့်ကို Design Tool ထဲကနေ Production Code တွေကို လှမ်းပြင်ခွင့် ပေးထားပါတယ်။ ဒါကြောင့် ဘေးကင်းအောင် ဘယ်လို လုပ်ဆောင်ရမလဲ ကြည့်ကြရအောင်။

## ၁။ နာမည်ပေးခြင်းသည် အရာရာ ဖြစ်သည် (Naming is Everything)
Plugin က Code ထုတ်ပေးဖို့ သင့် Variable နာမည်တွေကို အသုံးပြုပါတယ်။
*   **Slashes (`/`) ကို ပညာသားပါပါ သုံးပါ:** Plugin က Slash တွေကို အဆင့်ခွဲခြားမှု (Hierarchy) အဖြစ် သတ်မှတ်ပါတယ်။ `Button / Bg / Primary` လို့ ပေးလိုက်ရင် JSON ထဲမှာ အဆင့်ဆင့် တည်ဆောက်သွားမှာပါ။ တစ်သမတ်တည်း ဖြစ်ပါစေ။
*   **Special Characters တွေ ရှောင်ပါ:** စာလုံးတွေ၊ ဂဏန်းတွေနဲ့ Slashes တွေကိုပဲ သုံးပါ။ Emojis တွေ၊ ရှုပ်ထွေးတဲ့ သင်္ကေတတွေက Variable နာမည်ထဲမှာ ပါနေရင် Code ထုတ်တဲ့အခါ Error တက်တာ၊ JSON ပုံစံ ပျက်တာတွေ ဖြစ်စေနိုင်ပါတယ်။

## ၂။ Branch ကို လေးစားပါ
`main` branch ကို တိုက်ရိုက် Push လုပ်တာဟာ ဖျော်ဖြေတင်ဆက်နေတုန်း စင်ပေါ် ပြေးတက်သွားတာနဲ့ တူပါတယ်။ အရမ်း အန္တရာယ် များပါတယ်။
*   **အကောင်းဆုံး နည်းလမ်း:** `feat/design-tokens` သို့မဟုတ် `update-tokens` လိုမျိုး Design Update တွေအတွက် Branch သီးသန့် ခွဲထားပါ။
*   **ဘာကြောင့်လဲ?** ဒါမှသာ Developers တွေက သင့်အပြောင်းအလဲတွေကို "Pull Request" လုပ်နိုင်မယ်၊ ပြန်စစ်ဆေး (Review) နိုင်မယ်၊ Product အစစ်ထဲ မရောက်ခင် App ပျက်မသွားအောင် ကာကွယ်နိုင်မှာ ဖြစ်ပါတယ်။

## ၃။ Token လုံခြုံရေး
သင့် GitHub Token ဟာ Password တစ်ခုလိုပါပဲ။
*   သင့် Screen ကို Record လုပ်နေတာမျိုး၊ Share နေတာမျိုး ဆိုရင် **Settings tab ကို ဖုံးကွယ်ထားပါ**။
*   Token ကို (•••••) နဲ့ ဖုံးထားပေးပေမယ့်၊ ကိုယ်ထုတ်ထားတဲ့ Token ကို တခြားသူတွေနဲ့ ဘယ်တော့မှ မျှဝေမသုံးပါနဲ့။ အဖွဲ့သား တိုင်းကို ကိုယ်ပိုင် Token ထုတ်ခိုင်းပါ။

## ၄။ Variable Modes
Variable Modes (ဥပမာ "Light" နဲ့ "Dark") တွေ သုံးထားရင် နာမည်တွေ ရှင်းလင်းပါစေ။ Plugin က Collection ထဲမှာ တွေ့တဲ့ Mode *အားလုံး* ကို Export ထုတ်ပေးမှာပါ။ Production ထဲ မပါစေချင်တဲ့ "Draft" mode တွေ ရှိနေရင် Sync မလုပ်ခင် ရှင်းလင်းသင့်ပါတယ်။
