ဘယ်လို အလုပ်လုပ်သလဲ?

ဒီမှော်ဆန်တဲ့ လုပ်ဆောင်မှုတွေ ဘယ်လိုဖြစ်ပျက်သွားတာလဲ? ကဲ... နောက်ကွယ်က အကြောင်းအရာလေးတွေကို ကြည့်လိုက်ရအောင်။ Orchestra Sync ဟာ Figma နဲ့ GitHub ကြားက စကားပြန်တစ်ယောက်၊ စာပို့လုလင်တစ်ယောက် အဖြစ် လုပ်ဆောင်ပေးပါတယ်။

လုပ်ငန်းစဉ် အဆင့်ဆင့်ကတော့ ရိုးရှင်းတဲ့ ပုံပြင်လေးတစ်ပုဒ်လိုပါပဲ -

၁။ ချိတ်ဆက်ခြင်း (The Connection)​

ပထမဆုံးအနေနဲ့ Plugin က လုံခြုံစိတ်ချရတဲ့ ဆက်သွယ်ရေးလမ်းကြောင်းတစ်ခုကို တည်ဆောက်ပါတယ်။ သူက GitHub API ကို အသုံးပြုပြီး သင့်ရဲ့ Code Repository နဲ့ "လက်ဆွဲနှုတ်ဆက်" လိုက်ပါတယ်။ ပြီးရင် ဖိုင်တွေကို ဖတ်ရှုခွင့်၊ ရေးသားခွင့် ရဖို့ ခွင့်တောင်းပါတယ်။ ဒါမှသာ သူပေးပို့ချင်တဲ့ ပါဆယ်ထုပ်တွေကို ပို့ဆောင်ပေးနိုင်မှာလေ။

၂။ စုဆောင်းခြင်း (The Collection)​

ချိတ်ဆက်ပြီးသွားပြီဆိုရင် Plugin က သင့်ရဲ့ Figma File ကို ကြည့်ရှုပါတယ်။ သူက ပုံသဏ္ဍာန်တွေ၊ ပစ်ဇယ် (Pixels) တွေကို ကြည့်တာမဟုတ်ဘဲ Variables တွေကို လိုက်ရှုပါတယ်။ Primitives (raw values) နဲ့ Tokens (semantic values) တွေ စုစည်းထားတဲ့ "Variable Collections" တွေကို Scan ဖတ်ပါတယ်။

သင် (Conductor) က ဘယ် Collection တွေ အရေးကြီးတယ်ဆိုတာ Plugin ကို ပြောပြပေးရပါမယ်။ ပြီးရင် Colors, Spacing, ဒါမှမဟုတ် Typography စသဖြင့် "Sync Groups" တွေ ဖွဲ့ပေးရပါမယ်။ ဒါက Plugin ကို "ဒီ Design ဆုံးဖြတ်ချက်တွေကို ယူပြီး ထုပ်ပိုးလိုက်တော့" လို့ အမိန့်ပေးလိုက်တာပါပဲ။

၃။ ဘာသာပြန်ခြင်း (The Translation)​

ဒီအဆင့်ကတော့ Orchestra Sync ရဲ့ အဓိက ဉာဏ်ကြီးရှင် အပိုင်းပါပဲ။ Figma ကနေ မထွက်ခွာခင်မှာ Plugin က Variable နာမည်တွေကို Developers တွေ နားလည်တဲ့ ဘာသာစကားအဖြစ် ပြောင်းလဲပေးပါတယ်။

  • Web အတွက်: Button/Primary ကို CSS Variables တွေဖြစ်တဲ့ var(--button-primary) အဖြစ် ပြောင်းပေးပါတယ်။
  • Android အတွက်: Theme.colors.button_primary ဆိုတဲ့ Dot-notation ပုံစံ ပြောင်းပေးပါတယ်။
  • iOS အတွက်: Swift တွေသုံးတဲ့ Color.Button.Primary ပုံစံ ပြောင်းပေးပါတယ်။

ဒီလို ဘာသာပြန်ထားတဲ့ နာမည်တွေကို Figma Variables တွေရဲ့ "Code Syntax" နေရာမှာ တိုက်ရိုက် ဖြည့်သွင်းပေးလိုက်တဲ့အတွက် Developers တွေက ဖိုင်ကို ဝင်ကြည့်ရင်တောင် မှန်ကန်တဲ့ Code နာမည်ကို တွေ့မြင်နိုင်မှာပါ။

၄။ ပို့ဆောင်ခြင်း (The Delivery)​

နောက်ဆုံးအဆင့်မှာတော့ Plugin က တန်ဖိုးတွေ အားလုံး (နာမည်တွေ၊ တန်ဖိုးတွေ၊ Hex codes တွေ၊ Pixel values တွေ) ကို သေသပ်ပြတ်သားတဲ့ JSON ဖိုင်တစ်ခုအဖြစ် ထုပ်ပိုးလိုက်ပါတယ်။

ပြီးရင်တော့ ဒီအပြောင်းအလဲတွေကို "Commit" (Digital အလုံပိတ် ပါဆယ်ထုပ်) တစ်ခုအဖြစ် ဖန်တီးပြီး GitHub ပေါ်က သတ်မှတ်ထားတဲ့ Branch ဆီကို တွန်းပို့ (Push) လိုက်ပါတယ်။ ဒါဟာ Express Mail နဲ့ ပါဆယ်ပို့လိုက်သလိုပါပဲ "ရော့... ဒါ နွေရာသီ Update အတွက် အရောင်အသစ်တွေ" ဆိုပြီး ပို့လိုက်တာပါ။

Developers တွေက ဒီဖိုင်ကို လက်ခံရရှိမယ်၊ သူတို့ရဲ့ Build System က ဖတ်ရှုမယ်၊ ပြီးရင် သင့် App ကြီးက အလိုအလျောက် Update ဖြစ်သွားပါလိမ့်မယ်။
